# AI 무한도전 실험실

몰랑이 v16의 **외부 상태 저장·호기심 검색·NM 스타일 경계**를 바탕으로 만든 개인용 가상 예능 시제품입니다.
방송사 또는 출연진의 공식 서비스가 아닙니다. 프로필은 개인 감상용 가상 설정이고, 실제 방송 대사를 복제하지 않습니다.

## 무엇이 작동하나

1. 한국 시간의 날짜마다 멤버별 검색 주제를 골라 Brave 결과를 수집합니다. 같은 날짜를 다시 실행해도 기획안을 중복 생성하지 않습니다.
2. 출처 점수·관심 적합도·평가 이력·선택적 NM 점수로 후보를 정렬하고, 태호 AI가 **결말이 없는 기획안**을 하나 만듭니다. 기획안은 오래된 순서로 대기합니다.
3. 재생하면 멤버 한 명당 **별도의 모델 호출**로 대사와 행동을 만듭니다. 개인 기억, 관계, 지난 턴 10개, 인과 요약을 매번 전달합니다. 태호 AI가 12턴마다 돌발 사건을 투입합니다.
4. 매 턴 SQLite에 저장합니다. 100턴 뒤 평점을 입력하면 다음 회차의 태호·멤버 프롬프트와 소재 순위에 반영합니다. 이번 회의 부정적 감정은 15%, 긍정적 관계 변화는 30%만 다음 회에 남습니다.

## 시작

Python 3.11 이상에서 이 디렉터리로 이동합니다.

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Windows에서는 `.venv/bin/python` 대신 `.venv\\Scripts\\python.exe`를 사용하세요.

모의 모드에서 키나 인터넷 없이 상태 흐름을 확인합니다. **모의 모드의 대사와 검색 소재는 기계적으로 생성한 예시**입니다.

```bash
.venv/bin/python -m mudo.cli daily --demo
.venv/bin/python -m mudo.cli queue
.venv/bin/python -m mudo.cli play --limit 20 --demo
.venv/bin/python -m mudo.cli play --limit 80 --demo
.venv/bin/python -m mudo.cli review 1 review_example.json
```

실제 모델과 검색을 사용할 때는 환경 변수 `OPENAI_API_KEY`와 `BRAVE_API_KEY`를 설정하고 `--demo`를 빼세요. OpenAI 호환 로컬 모델은 `OPENAI_BASE_URL`과 `MUDO_MODEL`로 선택합니다. 예: `OPENAI_BASE_URL=http://localhost:11434/v1`, `MUDO_MODEL=사용하는_모델명`. 로컬 모델이라도 Brave 검색에는 인터넷과 검색 키가 필요합니다. SQLite 경로는 `MUDO_DB`로 지정할 수 있습니다.

```bash
.venv/bin/python -m mudo.cli daily
.venv/bin/python -m mudo.cli play --limit 100
.venv/bin/streamlit run app.py
```

앱에는 기획안 쌓기, 대기열, 최대 100턴 이어 재생, 일곱 멤버와 태호 AI 평가가 있습니다. 오래 걸리는 모델이라면 10~20턴씩 진행하세요. 모든 완료 턴은 저장됩니다. 한 번에 끝까지 실행하려면 CLI의 `play --limit 100`을 이용하세요.

## 매일 한 번 기획

PC나 서버의 작업 예약 도구에서 하루 한 번 `python -m mudo.cli daily`를 실행하세요. 리눅스의 KST 로컬 시계를 쓰는 예시는 `0 9 * * * cd /프로젝트/ai_mudo && /프로젝트/ai_mudo/.venv/bin/python -m mudo.cli daily`입니다. 다른 시간대에서 실행하면 `--day YYYY-MM-DD`를 한국 날짜로 전달하세요. PC가 꺼져 있으면 해당 날의 기획은 생기지 않습니다. DB가 로컬에 저장되므로 일시적인 GitHub Actions 러너에서 실행할 때는 **반드시 별도의 영속 저장소**가 필요합니다.

## NM 연결

몰랑이 압축파일에 있는 `organism/nm_guard.py`는 **학습된 Neural Markov가 아니라 휴리스틱 점수 규칙**이었습니다. 이 파일을 `mudo/molang_nm_guard.py`로 옮겨 출처 경계를 재사용합니다. 순위용 모델은 다음 순서로 적용합니다.

1. `MUDO_NM_MODULE`이 설정되면 그 파이썬 모듈의 `score(text) -> 0..1` 함수를 호출합니다. 여기로 별도 보유 중인 훈련된 NM 엔진을 연결할 수 있습니다. 반환값 밖의 숫자는 오류로 처리합니다.
2. 플러그인이 없다면 `corpus/episode_notes.txt`에 사용자가 직접 쓴 방송 **구조 요약** 세 줄 이상이 있을 때 로컬 단어 마르코프 기준을 사용합니다. 사용자가 재미와 유사도를 모두 4점 이상 준 회차의 기획안도 훈련 재료에 들어갑니다. 이 기준은 *신경망이 아니므로* UI에 `local_markov`로 표시합니다.
3. 어느 쪽도 준비되지 않았다면 `untrained`로 표시하고 출처·피드백 점수만 사용합니다. 학습되지 않은 NM을 사용한 척하지 않습니다.

이 점수는 소재의 **프로그램 결에 대한 적합성**을 가늠하는 보조치입니다. 사실성이나 실제 재미의 검증은 별도로 해야 합니다.

## 인물 구성과 이월

기본 `mudo/profiles.json`은 편의를 위한 **가상 7인 편성**입니다. 2018년 실제 방송의 특정 한 시점 편성과 같다는 뜻이 아닙니다. 선호하는 멤버 7명과 검색 성향으로 고쳐 사용할 수 있고, 다른 JSON 경로는 `MUDO_PROFILES`로 지정할 수 있습니다. 기존 DB의 멤버 id를 바꾸면 이전 기억·평가와 이어지지 않습니다.

관계는 방향이 있습니다. 한 멤버가 다른 멤버에게 느끼는 관계 점수는 반대쪽과 다를 수 있습니다. 한 회 안에서는 사건에 따라 움직이고, 사람의 회차 평가 이후 기본 관계 쪽으로 돌아갑니다. 사건 원문은 저장되지만 개인의 이번 회 감정과 개인 메모는 새 회차에서 초기화됩니다. 평가 문장과 관계의 일부가 다음 회로 넘어갑니다.

## 현재 한계

- 멤버와 태호의 선택은 각각 별도 모델 호출이지만, 같은 제공업체·기반 모델을 쓸 수 있습니다. 독립적으로 훈련된 인공지능 8개라는 뜻은 아닙니다.
- 이 파일에는 저작권이 있는 방송 대본, 검증된 캐릭터 자료, 훈련된 NM 모델, 실제 API 키, 실제 방송 로그가 포함되지 않습니다. 원본 대사 대신 직접 정리한 구조·관계 기록으로 시작하세요.
- 유사도와 재미 평가는 사용자 평점에 의존합니다. 모델 교체에 따른 일관성과 장기 이야기 품질은 아직 벤치마크하지 않았습니다.
- 대화 횟수가 길어질수록 비용이 커집니다. 재생 버튼은 한 번 누를 때 지정한 턴만 수행하고 실패 직전까지 저장합니다.
